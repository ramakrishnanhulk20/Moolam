2. giveFeedback has no feedbackAuth on this deployment
   The integration plan said giveFeedback takes a feedbackAuth signed by
   the agent owner. It does not. The deployed function is exactly the one quoted
   in the ERC-8004 specification (https://eips.ethereum.org/EIPS/eip-8004), eight arguments and
   no signature:

     giveFeedback(uint256 agentId, int128 value, uint8 valueDecimals,
       string tag1, string tag2, string endpoint, string feedbackURI,
       bytes32 feedbackHash)

   Selector check against the implementation runtime bytecode (a PUSH4 of each
   selector is present):
     0x3c036a7e giveFeedback(uint256,int128,uint8,string,string,string,string,bytes32)
     0x81bbba58 getSummary(uint256,address[],string,string)
     0x232b0810 readFeedback(uint256,address,uint64)
     0xd9d84224 readAllFeedback(uint256,address[],string,string,bool)
     0x42dd519c getClients(uint256)
     0x4ab3ca99 revokeFeedback(uint256,uint64)
     0xc2349ab2 appendResponse(uint256,address,uint64,string,bytes32)
     0xf2d81759 getLastIndex(uint256,address)
     0xbc4d861b getIdentityRegistry()
   There is no authorise, no permit, no EIP-712 domain and no nonce function in
   the bytecode. Nothing on chain would verify a signature from signFeedbackAuth,
   so that function cannot be written against this contract, and the DONE MEANS
   test for it cannot be written either.

3. The deployer cannot leave feedback about its own agent
   ownerOf(10248) on the Identity Registry -> 0x559F357aDa3A96d11AEa679eC0D622E4AF15F67c
   which is the deployer wallet.

   Simulated giveFeedback from the deployer (eth_call, no transaction):
     Error: execution reverted: Self-feedback not allowed

   Simulated from a non-owner address (0x...dEaD), same arguments:
     succeeds, returns 0x

   So the planned fallback, "VERIFIER_PRIVATE_KEY if set, else the
   deployer key", cannot work: VERIFIER_PRIVATE_KEY is not in the root .env, and
   the deployer key is the one address the registry refuses. A real feedback
   transaction needs a second funded wallet that is not the agent owner.

4. What is needed to unblock, in one line each
   a. A verifier wallet: generate a key, put VERIFIER_PRIVATE_KEY in .env, send
      it enough MON for gas plus the 10 MON Monad keeps reserved. Both the .env
      edit and the funding transfer are outside this order's permissions.
   b. Drop signFeedbackAuth and agentAuth.ts from the interface: there is nothing
      on chain for them to authorise.
   c. postFeedback then takes (agentId, matched, distance, passportId, signerKey)
      and calls giveFeedback with value = the score, valueDecimals = 0, tag1
      "moolam", tag2 "verification", endpoint the verify URL, feedbackURI and
      feedbackHash pointing at the verification result.
   d. readReputation reads getSummary(agentId, [verifierAddress], "moolam",
      "verification"), because getSummary needs a non-empty client list.
